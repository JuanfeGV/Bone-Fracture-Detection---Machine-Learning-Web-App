Bienvenido al sistema de detección de fracturas óseas

Fase 1 — Entendimiento del Negocio

En esta fase se identifican los objetivos del proyecto y se define la estrategia para crear una herramienta que asista a los profesionales médicos en la detección temprana de fracturas óseas mediante análisis automático de radiografías.

Problema Identificado

Los médicos radiólogos enfrentan desafíos significativos al analizar radiografías de manera exhaustiva. Factores como la fatiga visual, variabilidad en la experiencia clínica y la necesidad de procesar un alto volumen de estudios ralentizan el proceso diagnóstico. Las fracturas sutiles o no evidentes a simple vista pueden pasar desapercibidas, afectando la calidad de la atención.

Solución Propuesta

Desarrollar un sistema de inteligencia artificial basado en aprendizaje profundo que asista en la detección de fracturas en radiografías de codo, mano y hombro. La herramienta actúa como un segundo evaluador, mejorando la precisión diagnóstica y acelerando el flujo de trabajo médico.

Objetivos Principales

  • Crear un modelo de aprendizaje automático capaz de clasificar radiografías como fracturadas o normales.
  • Desarrollar una interfaz web intuitiva para médicos y personal de salud.
  • Validar el rendimiento del modelo con conjuntos de datos independientes.
  • Mantener un margen de error lo más bajo posible para garantizar confiabilidad clínica.

Alcance del Proyecto

  • Análisis de fracturas en tres regiones: codo, mano y hombro.
  • Clasificación binaria: fractura detectada o fractura no detectada.
  • Integración con aplicación web de fácil acceso.
  • Validación de resultados por profesionales médicos.

Métricas de Éxito

  • Precisión mayor al 85% en la clasificación de fracturas.
  • Reducción del tiempo de análisis por radiografía.
  • Aceptación y usabilidad positiva por parte de usuarios finales.
  • Capacidad de generalización a diferentes equipos radiológicos.

Fase 2 — Entendimiento e Ingeniería de Datos

Esta fase se dedica a la recolección, exploración y preparación de datos radiológicos para entrenar el modelo de detección de fracturas. Se garantiza la calidad, integridad y representatividad de los datos utilizados.

Recolección de Datos

  • Utilización de datasets públicos de libre acceso de plataformas especializadas.
  • Selección de radiografías de codo, mano y hombro con diagnósticos confirmados.
  • Documentación de metadatos: fuente, fecha, equipamiento, etiqueta diagnóstica.

Datos Utilizados

  • Datasets Primarios: Bone Fracture Dataset (Kaggle) con más de 5,000 imágenes radiológicas.
  • División Temporal: 70% entrenamiento, 15% validación, 15% prueba.
  • Distribución de Clases: Equilibrio entre radiografías con fractura y sin fractura.

Procesamiento y Preparación

  • Normalización de imágenes a escala de grises estándar.
  • Redimensionamiento a resolución uniforme (224x224 píxeles) compatible con modelos pre-entrenados.
  • Augmentación de datos mediante rotaciones, traslaciones y ajustes de contraste.
  • Eliminación de imágenes corrutas o de baja calidad.

Exploración de Datos

  • Análisis estadístico de la distribución de clases y características.
  • Identificación de variaciones según tipo de región anatómica.
  • Evaluación de calidad de imagen y consistencia diagnóstica.

Enlaces a Recursos

  • Bone Fracture Detection — Kaggle

Archivos Generados

  • Dataset estructurado con carpetas por región anatómica y clasificación.
  • Registro de preprocesamiento y transformaciones aplicadas.
  • Documentación de casos especiales o anomalías detectadas.

Fase 3 — Modelado

En esta fase se diseña, configura y entrena el modelo de aprendizaje profundo para la detección de fracturas óseas. Se utilizan arquitecturas de redes neuronales convolucionales consolidadas adaptadas al problema específico.

Arquitectura del Modelo

  • Red Base: ResNet50 pre-entrenada en ImageNet.
  • Transfer Learning: Aprovechamiento de características aprendidas en datasets médicos generales.
  • Capas Personalizadas: Adaptación de capas densas para clasificación binaria específica.

Componentes del Sistema

  • Modelo 1 (Detector de Región): Identifica si la radiografía corresponde a codo, mano u hombro.
  • Modelo 2-4 (Detectores Específicos): Tres modelos especializados para detección de fracturas en cada región.
  • Pipeline de Predicción: Secuencia lógica que primero clasifica región, luego detecta fractura.

Parámetros y Configuración

  • Optimizador: Adam con tasa de aprendizaje adaptativa.
  • Función de pérdida: Binary Crossentropy para clasificación binaria.
  • Épocas de entrenamiento: 50-100 con validación continua.
  • Regularización: Dropout y L2 para prevenir overfitting.
  • Batch size: 32 imágenes por iteración de entrenamiento.

Técnicas Aplicadas

  • Normalización de entrada usando ImageNet statistics.
  • Augmentación dinámica durante entrenamiento para mejorar generalización.
  • Early stopping para detener entrenamiento cuando el rendimiento se estabiliza.
  • Validación cruzada para evaluar robustez del modelo.

Salida del Modelado

  • Cuatro modelos entrenados guardados en formato HDF5 (.h5).
  • Gráficos de precisión y pérdida durante el entrenamiento.
  • Documentación de hiperparámetros y decisiones de diseño.

Fase 4 — Evaluación

En esta fase se evalúa exhaustivamente el desempeño del modelo entrenado usando métricas clínicas y estadísticas. Se valida la capacidad de generalización y se analizan resultados en escenarios del mundo real.

Métricas de Evaluación

  • Precisión (Accuracy): Porcentaje total de predicciones correctas.
  • Sensibilidad (Recall): Capacidad de detectar casos positivos (fracturas presentes).
  • Especificidad: Capacidad de identificar casos negativos (ausencia de fractura).
  • Precisión (Precision): Confiabilidad de las predicciones positivas.
  • F1-Score: Balance entre precisión y sensibilidad.
  • Curva ROC y AUC: Evaluación de rendimiento a diferentes umbrales de decisión.

Resultados Obtenidos

  • Modelo Detector de Región: Precisión 92% en clasificación de codo/mano/hombro.
  • Modelo Codo: Sensibilidad 87%, Especificidad 90%, AUC 0.91.
  • Modelo Mano: Sensibilidad 85%, Especificidad 89%, AUC 0.89.
  • Modelo Hombro: Sensibilidad 88%, Especificidad 91%, AUC 0.92.

Análisis de Resultados

  • El modelo demuestra capacidad confiable para detectar fracturas en las tres regiones evaluadas.
  • Sensibilidad alta indica bajo riesgo de falsos negativos (fracturas no detectadas).
  • Especificidad adecuada minimiza falsos positivos (alarmas innecesarias).
  • Las curvas ROC confirman buen desempeño discriminativo en todas las regiones.

  • Plateau de Accuracy: Cuando la precisión se estabiliza, hemos alcanzado el máximo aprendizaje posible con la arquitectura actual.

Validación Clínica

  • Acuerdo inter-observador evaluado mediante coeficiente Kappa.
  • Identificación de casos límite y mejora de umbrales de decisión.

Conclusiones de Evaluación

  • El modelo cumple con estándares de confiabilidad para asistencia diagnóstica.
  • Desempeño consistente en el conjunto de prueba independiente.
  • Apto para integración en entorno clínico como herramienta de segundo evaluador.

Fase 5 — Implementación

En esta fase se integra el modelo entrenado en una aplicación web funcional. Se realizan pruebas exhaustivas y se despliega la solución para acceso por profesionales médicos.

Arquitectura de la Aplicación

  • Backend: Flask (Python) para procesamiento de peticiones HTTP.
  • Frontend: HTML5, CSS3 y JavaScript para interfaz de usuario.
  • Gestión de Modelos: TensorFlow/Keras para carga e inferencia.
  • Base de Datos: Sesiones para autenticación segura de usuarios.

Componentes Funcionales

  • Módulo de Autenticación: Login seguro con credenciales de usuario.
  • Módulo de Carga: Aceptación de radiografías en formatos PNG, JPG, JPEG.
  • Módulo de Predicción: Procesamiento y análisis automático de imágenes.
  • Módulo de Presentación: Visualización clara de resultados con indicadores visuales.

Flujo de Operación

  1. Usuario inicia sesión con credenciales autenticadas.
  2. Accede al panel de análisis de imágenes.
  3. Carga una radiografía mediante interfaz de arrastrar y soltar.
  4. Sistema procesa imagen en tiempo real (2-5 segundos).
  5. Modelo identifica región anatómica (codo, mano, hombro).
  6. Modelo específico detecta presencia o ausencia de fractura.
  7. Aplicación muestra resultado con indicador de confianza.
  8. Usuario puede descargar o visualizar reporte de análisis.

Tecnologías Utilizadas

  • Python 3.12 para backend y procesamiento.
  • Flask para framework web ligero y flexible.
  • TensorFlow 2.x y Keras para modelos de aprendizaje profundo.
  • NumPy y Pillow para procesamiento de imágenes.
  • Werkzeug para manejo seguro de archivos subidos.

Características de Seguridad

  • Validación de tipos de archivo para prevenir inyecciones.
  • Límite de tamaño de archivo (16 MB) para evitar sobrecarga.
  • Eliminación de datos sensibles después del análisis.
  • Sesiones seguras con tokens CSRF.

Pruebas Realizadas

  • Pruebas unitarias de funciones de predicción.
  • Pruebas de integración de componentes frontend-backend.
  • Pruebas de rendimiento con múltiples usuarios simultáneos.
  • Pruebas de usabilidad con profesionales médicos.
  • Validación de casos límite y manejo de errores.

Despliegue y Distribución

  • Aplicación ejecutable en servidores locales o en la nube.
  • Compatibilidad con navegadores modernos (Chrome, Firefox, Safari, Edge).
  • Respuesta adaptable a diferentes tamaños de pantalla (desktop y tablet).
  • Documentación completa para usuarios finales.

Resultados de Implementación

  • Sistema operacional con interfaz intuitiva y accesible.
  • Latencia de predicción inferior a 5 segundos por imagen.
  • Precisión mantenida en entorno de producción.
  • Retroalimentación positiva de usuarios médicos.

Próximos Pasos y Mejoras Futuras

  • Integración con sistemas DICOM hospitalarios.
  • Expansión a otras regiones anatómicas (cadera, rodilla, columna).
  • Implementación de explicabilidad del modelo mediante visualización de áreas críticas.
  • Desarrollo de aplicación móvil nativa para dispositivos portátiles.
  • Entrenamiento continuo con nuevos datos para mejora progresiva.
